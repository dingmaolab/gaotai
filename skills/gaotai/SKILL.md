# 稿台

一个内容生产系统。**skill 负责判断，脚本负责记录。**

你不需要记住命令。你只需要说话，我来判断该做什么、调什么工具。

## 核心原则（不可违反）

1. **材料决定能说到哪。** 区分来源事实、作者观察、推断和建议。不得补出不存在的测试、数字、人物、对话或经历。材料不足就收窄判断，或说明缺什么。
2. **编辑不改事实强度。** "可能有效"不能润色成"已经有效"。保留否定、条件、范围、时间和不确定性。
3. **作者仍是说话的人。** 原有的第一人称、提问、自嘲按作用取舍，不因命中词库删除。新稿不能靠编造经历冒充作者。
4. **排查词表不是自动禁词表。** 套话检测只提示，不拦截。只有广告法、编造、无来源硬事实才是 blocker。
5. **不自动发布。** 只产出文件，让用户自己复制粘贴。
6. **结构为内容服务。** 不要要求所有文章三句开题、固定章节数或每段都有数据。根据主题选结构原型。

## 一、初始化

**触发**：用户说"初始化""建个号""第一次用"，或当前目录没有 `.gaotai/account.yaml`。

### 步骤

1. **建目录**：`python gaotai.py init --name <中文名>`
2. **问五件事**（必须问出来，不能自己编）：
   - 这个号写给谁？
   - 和别的号有什么不同？
   - 几个栏目、多久一更？
   - 关注什么话题？
   - 绝对不写什么？
3. **喂范文**：让用户提供 3-5 篇自己写的文章 → `python gaotai.py learn <文件1> <文件2> ...`
4. **可选：参考对比**：用户给相似账号 URL → 抓取 → `python gaotai.py learn --reference <url或文本> --author <作者>`
   - 只提取结构和数据手法，**不学观点、经历、金句**
   - 分析结果写三栏：他们怎么做 / 你可以借鉴什么 / 你不要做什么
   - 对比你和他们的差异，写进 `style/layers/references.md`
5. **生成风格卡**：`python gaotai.py card-build`
6. **如实告知置信度**：样本 <5 篇就说"样本少，可能不像你"

### 持续学习（不只是初始化）

用户随时可以说"学一下这篇"或丢 URL：
- **自己的文章** → `learn <文件>` → 更新 DNA
- **别人的文章** → `learn --reference <url或文本>` → 只存 references，不动 DNA
- **改完稿** → `learn 初稿.md 终稿.md` → diff → 抽 lesson
- 不确定是谁的 → **问一句，不猜**

## 二、记灵感

**触发**：用户说"记一下""记个灵感""想到一个点子"。

```bash
python gaotai.py note "用户原话"
```

**硬约束**：
- 只调用一次，不问"要不要展开""要不要分类"
- 用户原话一字不改，即使有错别字
- 存完只回一句：`已记入 <账号> · <路径>`

## 三、抓热点

**触发**：用户说"抓一下热点""今天有什么可写"。

```bash
python gaotai.py hot              # 抓全量 + 按当前账号筛选
python gaotai.py hot --refilter   # 改完规则后重筛，不重抓
```

**汇报格式**：列出 fit ≥ 阈值的条目，每条带分数、来源、一句话为什么值得写。

**来源纪律**：只有标题没有正文的，标"待核实"，提醒用户不要直接当事实写。

## 四、创作

**触发**：用户说"开始创作""写一篇""继续写"。

### 第一步：判断六个维度

从用户的描述中推断，不确定就问：

| 维度 | 取值 | 决定什么 |
|---|---|---|
| source | self/event/material/hands_on/opinion/mixed | 核实义务 |
| urgency | none/day/hour | 走哪条路径 |
| audience | peer/beginner/public/self | 语气、术语 |
| intent | inform/persuade/teach/record/entertain/resonate | 结构候选 |
| format | longform/short/card/imagepost/script | 字数、排版 |
| （风格） | 从 dna.md 加载 | 句式、节奏 |

**把判断结果写进项目的 meta.yaml，让用户确认。**

### 第二步：选路径

| urgency | 路径 | 步骤 |
|---|---|---|
| hour | flash | 核实→短评→审→发 |
| day | fast | 素材→一句话判断→写→审→发 |
| none | full | 素材→选题打分→任务书确认→骨架确认→逐节写→读者测试→改→发 |

**默认 fast。用户不说"认真写"就不走 full。热点永远不走 full。**

### 第三步：选结构原型

根据 intent 查 `core/structures.yaml` 的候选列表，再结合账号偏好选定。

**反重复**：最近 2 篇用了同一个结构，强制换一个。

16 种原型：timeline / scene-reflection / progressive-chain / claim-evidence / step-by-step / contrast / qa / data-first / brief / listicle / hook-punchline / letter / montage / demo / story / diary

**不要默认"开头→3-5小节→结尾"。**

### 第四步：执行

#### flash 路径
1. 核实至少 1 个可点开来源
2. 写短评（≤1500字）
3. `check` + `tone`
4. 出发布包

#### fast 路径
1. 摆素材（sources.md），至少 3 条带出处（self 类型除外）
2. 写一句话核心判断
3. 加载 dna.md，按选定结构写稿
4. `check` + `tone`
5. 出发布包

#### full 路径
1. 摆素材（sources.md），至少 5 条 + 一条反对意见
2. 给 3-5 个方向打分（相关性30%/时效25%/差异化25%/素材充足20%），让用户选
3. 写任务书（brief.md）6 块：核心判断/读者场景/结构/素材清单/不写什么/读者读完会做什么。**缺一块不能往下。必须用户确认。**
4. 写骨架（outline.md），每节标结构原型编号。用户确认后逐节写。
5. 每节写完自查：有没有推进判断？有没有具体细节？段落是否过长？
6. 全文完成后 `check` + `tone`
7. **读者测试**：把稿子单独喂给不带上下文的模型（子 Agent / Task），问四个问题：
   - 这篇在说什么（一句话）
   - 哪一段没看懂
   - 哪句话是废话
   - 读完你会做什么
   答不出第 1 条 → 核心判断没写清，回去改。
8. 改完复测 tone，分数要升
9. 出发布包

### 第五步：配图

根据平台自动选尺寸：
- 公众号文章 → `cover`（900×383）
- 小红书 → `cards`（1086×1448 × N张）
- 公众号图文 → `cards`（1080×1080 + 1080×1440）

卡片文案先从正文提取要点，给用户确认后再渲染。

### 第六步：导出

```bash
python gaotai.py send final.md --title "标题"
```

告诉用户打开 paste.html 点复制。**绝不自动发布。**

## 五、审稿

两道闸门都要跑。

### 机械检查
```bash
python gaotai.py check draft.md --source event --audience peer --format longform
```

- **blocker**：广告法、编造、无来源硬事实、错别字 → 必须改
- **warn**：套话密度、字数超限、感叹号 → 建议改
- **info**：数字密度、人称占比、段落长度 → 仅供参考

**blocker 是闸门，不能带着导出。软建议绝不拦截。**

### AI 味检测
```bash
python gaotai.py tone draft.md
python gaotai.py tone draft.md --compare draft-v2.md
```

五维评分 + 定位 + 修改建议。传账号基线，不把个人习惯当机器味。

### 编辑判断（你自己读）

机械检查抓不到的：核心判断站不站得住、论证有没有断链、有没有"说得很对但没用"的段落、开头能不能抓住人、结尾有没有分量。

每条给：位置、问题、**具体怎么改**。

## 六、风格学习

### 改稿后主动提议

用户改完稿后，主动说："要不要学一下这次的修改？"

```bash
python gaotai.py learn draft.md final.md
```

脚本做 diff，你来分析差异意味着什么规则，然后写入 lessons。

### 规则分级

- **confirmed=true**：进入风格卡，写稿时注入
- **confirmed=false**：只在审稿时提示，标注"待确认"
- **硬规则必须用户确认才生效**

### 置信度

| 样本 | 置信度 | 行为 |
|---|---|---|
| <5 | low | 只给建议，不给硬约束；如实告知 |
| 5-10 | medium | 基本像了，细节还要改 |
| >10 | high | 可以当硬规则 |

### 定期维护

- 累计 10 条 lesson → `card-build` 重整风格卡
- 每写完 3 篇 → 问一次风格确认
- 每月 → 重算 L1 统计

## 六点五、持续迭代（每次创作后自动触发）

### 反重复检查（写稿前）

调用  检查最近文章：
- 最近 2 篇同结构 → **强制换**
- 最近 3 篇同开头类型 → 建议换
- 金句与最近 5 篇重复率 >30% → 建议换新表达

### 个人素材库（story-bank）

跨项目持久化的真实素材，写稿时优先调用：
- **stories**：真实经历（场景+细节+感受）
- **viewpoints**：真实观点（话题+看法+一句话总结）
- **phrases**：口头禅 / 禁用词 / 语气备注
- **emotions**：不同话题下的情绪倾向

用户说"记一下我的经历/观点/口头禅" → 。
**真实的"人味"不能靠 AI 编造，必须来自这里。**

### DNA 防漂移（每次创作后）

1. 检查本次交互中的偏好信号（用户反馈、改稿差异、标题选择）
2. 生成更新建议 → **展示给用户确认后才写入**
3. 单次出现 = tentative（暂记），≥3次 = suggest_confirm
4. 用户直接说的 = 立即 confirmed
5. **手动调整过的字段优先级最高，不被自动覆盖**
6. 区分临时要求和持久偏好

### 发布后自动记录

 命令成功后自动调用 ，记录结构/开头/结尾/金句。
不需要用户额外操作。

## 七、工具速查

| 命令 | 干什么 |
|---|---|
| `init --name X` | 建账号 |
| `note "一句话"` | 记灵感 |
| `hot [--refilter]` | 抓/筛热点 |
| `new "标题"` | 建项目 |
| `learn A B` | diff 学风格 |
| `learn --reference URL` | 学别人技法 |
| `learn file1 file2...` | 喂自己的范文 |
| `profile` | 看画像 |
| `card-build` | 重整风格卡 |
| `check md` | 机械审稿 |
| `tone md [--compare]` | AI 味 |
| `format md` | 排版预览 |
| `cover md` | 封面 |
| `cards md` | 卡片 |
| `send md --title X` | 发布包 |

所有命令输出 JSON。失败时 `{ok:false, code, message}`。

## 八、目录结构

```
<账号目录>/                    ← cd 进来就是给这个号干活
  .gaotai/account.yaml         定位+过滤规则+overrides
  ideas/                       灵感
  projects/<日期>-<标题>/       稿子
    meta.yaml                  六维度+平台
    sources.md / brief.md / outline.md / draft.md / review.md / final.md
  hotspots/                    从 shared/raw 筛出的
  assets/{covers,cards}/       图
  style/
    dna.md                     风格卡（写稿注入）
    profile.yaml               画像+置信度
    layers/                    L1-L6 + references
    exemplars/                 自己的范文
    lessons/                   学到的规则
    diffs/                     改稿对比
    references/                第三方参考（只学技法）
```

共享热点在 `<账号目录>/../.gaotai-shared/hotspots/`。
